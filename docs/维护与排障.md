# 维护与排障

本页面向需要手动启动、升级、清理或排查字体的用户；日常安装、聊天使用和基础配置见 [README](../README.md)。

## 自动准备与服务生命周期

插件默认安装当前绑定的内置分析服务 Stock Robot 版本（`main.py` 的 `MANAGED_RELEASE_TAG`），不追随开发分支或自动选择 latest。服务由插件在 AstrBot 所在环境自动准备，固定连接 `127.0.0.1`，只需按需更换端口。

首次准备包括：

1. 下载插件绑定的已验证版本源码
2. 创建独立环境
3. 安装锁定依赖
4. 检查程序
5. 启动分析服务

AstrBot 主日志和插件数据目录的 `service.log` 会记录 `[1/5]` 至 `[5/5]` 阶段；序号表示当前阶段，各阶段耗时不同，不代表完成百分比。准备期间每 30 秒记录总耗时及最近一条脱敏输出；没有新输出也会说明正在等待。

插件复用同一端口上健康的已有分析服务前，会核对实际版本是否与绑定版本一致；停用插件不会关闭仅复用的服务。插件自己创建的服务在停用时回收。自建进程仍存活但健康检查失败时，先查看日志诊断，不会自动杀掉该进程并反复重启。

需要手动启动时，进入已安装 Stock Robot 的目录后运行，例如 Windows PowerShell：

```powershell
./.venv/Scripts/stock-robot.exe run --host 127.0.0.1 --port 25618
```

旧配置迁移只自动处理本地 HTTP 地址并保留端口；旧远程、带路径或 HTTPS 地址会明确提示人工处理，避免误建另一份实例。迁移前建议保留一份配置备份。旧配置明确关闭清理或自定义过安装时限的，保留原值；自动准备开关不再提供，旧关闭值不再生效。

**Docker 部署注意：** `127.0.0.1` 指向 AstrBot 容器自身，不是宿主机或其他容器。本插件不提供远程或跨容器地址配置，请确保插件数据目录已持久化。

安装优先使用 uv，否则使用 Python venv/pip；依赖按带哈希的锁清单安装。新安装只装核心依赖，旧就绪 RAG 环境保留，不自动卸载旧包。来源标签、查询渠道和下载摘要记录在活动运行时的 `src/.bootstrap-source.json` 与 `install-state.json` 中；活动运行时位置见 `instance/active-runtime.json`，旧根目录安装位于 `instance/`。下载摘要是实际内容的记录，不代表发布方签名验证。


## 升级与数据保留

插件与 Stock Robot 服务分别更新。默认情况下，插件升级会在后台把它自己在本机回环地址创建、且未使用自定义源码的服务升级至该插件已验证的绑定版本。候选源码与依赖完成自检后才切换，失败会回滚上一版本；健康检查通过后只保留当前活动版本，上一版和旧根目录安装产物会被删除，因此不再保留本地运行期回滚副本。配置、报告与缓存不受影响。

自动安装的数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_stock_robot/`：

| 路径 | 内容 |
| --- | --- |
| `service.log` | 安装与服务启动日志 |
| `delivery_tmp/` | 报告交付副本及任务元数据 |
| `delivery_diagnostics/` | 不含报告全文的简要任务诊断 |
| `instance/.stock_robot/` | 模型配置、凭据、缓存与运行日志 |
| `instance/reports/` | 已生成的报告 |
| `instance/src/`、`instance/venv/`、`instance/install-state.json` | 首次安装的旧根目录布局；活动版本迁入 `.releases` 并确认健康后自动删除 |
| `instance/.releases/` | 固定路径中的当前版本源码与独立环境；成功启动后只保留活动版本 |
| `instance/active-runtime.json` | 活动版本指针；健康确认后不再保留上一版 |
| `waiting.sqlite3` | 会话等待队列及尚未完成的任务状态 |

首次安装使用的根目录布局 `instance/src`、`instance/venv`、`instance/install-state.json` 会在活动版本迁入 `.releases` 并确认健康后自动删除；`instance/.stock_robot/`、`instance/reports/` 等数据保留。候选启动失败时仍会回滚上一版；健康确认后若当前版本在运行期损坏，需要重新安装，不能依赖本地上一版回滚。

查看实际占用（Linux/Docker）：

```bash
cd /path/to/AstrBot/data/plugin_data/astrbot_plugin_stock_robot/instance
cat active-runtime.json
du -sh .releases/* src venv 2>/dev/null
```

需要主动重装自动安装的服务时：

1. 停用插件，确认插件创建的服务进程已退出，并备份插件数据目录。
2. 移除安装产物：`instance/src/`、`instance/venv/`、`instance/install-state.json`，以及存在时的 `instance/.releases/`、`instance/active-runtime.json`。这些路径仅在停用且备份后处理。
3. 保留 `instance/.stock_robot/` 与 `instance/reports/`，重新启用插件。

新安装仅使用插件声明已验证的绑定版本与核心依赖。自定义源码与可选依赖入口不再提供；旧自定义来源明确提示人工迁移，不自动替换。已经就绪的旧 RAG 环境保留依赖集，不自动卸载。配置目录包含 API Key，分享日志或备份时请隐去凭据。

## 升级期间的等待请求

服务暂不可用时，每个会话（群聊所有成员共享）最多保留最新三个不同标的，重复代码合并；超出时告知被替换的标的。恢复后 AI 统一询问是否继续，任意群成员均可明确确认，由 AI 理解并调用受校验的确认工具。确认前不会分析。

首次询问送达后等待 30 分钟；无人确认则最后提醒一次并清空。期间同一会话提出新的分析请求，会清空旧等待队列并正常处理新请求；普通聊天不清空。

确认后依次处理。恢复投递使用该会话当前模型生成自然衔接，不读取或写入完整聊天历史；AI 文案生成或发送失败时不会发送研报。异常最多尝试三次，间隔 30 秒，单次 AI 生成与文字发送合计最多 30 秒；报告已生成后重试不会重新分析。失败报告与诊断保留 72 小时。

队列和已生成报告的投递进度可跨重载恢复。若进程在分析请求发出后、结果保存前中断，由于服务接口无幂等请求号，该项停止自动重跑并保留诊断，避免重复分析。消息平台还须支持主动发送；这些能力须在实际平台验收。

## 磁盘清理与报告保留

插件会自动保留完整 Markdown 和有效 PNG 副本：成功交付保留 24 小时，渲染或发送失败保留 72 小时；图片失败但文件成功、取消和异常退出均按失败处理。期限从任务结束计算，异常退出从下次恢复检查计算，用户可在保留期内复制保存。ZIP 仅用于上传，上传结束即回收。

已结束任务产物预算为 256 MiB：先清理到期产物，仍超限淘汰最旧任务。期限是上限，容量压力下可能提前删除。任务元数据计入产物预算；未知内容或无法验证归属的旧目录保留并提示，不会为了达标盲删。活动任务和上传中的文件不参与淘汰。

简要诊断保留 7 天，预算 16 MiB，记录阶段、耗时、错误类别和清理原因，不复制报告全文或凭据。每次报告交付任务对应一份诊断。安装和运行共用 `service.log`，每份 10 MiB、最多 5 份（含当前文件），历史日志最多保留 7 天；已有超大日志只保留预算内尾部。清理在初始化、每 10 分钟和新任务开始前执行，也在交付结束后检查产物预算。

运行时目录不占用报告预算。每次成功启动后，插件只保留 `.releases` 中的活动版本，并删除上一版和旧根目录安装产物；删除在后台线程执行，Windows 文件被占用或只读时有限重试，仍失败会在下次启动继续清理。未知目录、无自举器标记的目录不会删除。

`cleanup_previous_reports` 新安装默认开启，已有显式关闭值保留，修改后重载生效。实际清理由内置分析服务执行：在服务启动时和其后每 6 小时扫描报告库，删除超过 7 天的个股、指数和黄金报告单元，即 Markdown 与同名结构快照一起删除；快照摘要不匹配、文件名或目录不符合约定、目录里有未知文件的报告一律保留。保留期固定为 7 天，不提供按天数调整的配置项。清理使用服务自己的跨进程锁，删除失败留到下一轮重试。

插件在启动自建服务前把开关写入 `instance/.stock_robot/config.yaml`，并用数据目录中的同步基线区分插件侧和服务端修改：任一侧单独修改都会同步到另一侧，两边同时修改时以服务端为准。复用外部服务时不读取、不修改它的配置。清理范围不包含回测、雷达、会话、配置、数据库、依赖环境和用户另存副本；扫描间隔可在该服务配置页的完整配置文件编辑器中修改。

本功能不新增第三方依赖或系统服务。产物、诊断和插件日志预算合计约 322 MiB，活动任务、服务原始报告和依赖占用另算，不是整个插件或主机的硬容量限制。写盘或删除失败会记录警告并继续服务，磁盘完全耗尽时仍可能导致文件上传失败。

## 额外分析开关

`extra_analysis_enabled` 默认关闭，升级后缺项同样关闭。开启后对**新生成的个股报告**增加有效维度评分、依据充分时的规则信号与 AI 解读，对**新生成的指数报告**增加规则判断与 AI 解读，指数不新增评分、模型信号或仓位；关闭时保留行情、财报、新闻、来源、日期、缺失说明和可复核指标。黄金、配置雷达、回测保持原有行为，历史报告不会随开关变化重写。开启后 AI 仍受模型配置与 `llm.enabled` 约束；本开关不清除模型凭据，也不关闭全局 LLM。

插件在启动自建服务前把开关写入服务配置，并与服务 Web 配置页的“启用额外分析”双向同步。该设置属于整个分析服务，Web、CLI、订阅以及其他复用该服务的客户端的新报告会一并遵循。复用外部启动的服务或另一插件实例管理的服务时，插件不写其配置；开关不一致、服务版本过旧（配置接口没有 `analysis` 字段）或写入失败时，会在首次分析前发送一次性提示并记录日志，界面显示不代表已经生效。

## 报告图片与字体

报告通过 AstrBot 原生字生图生成，不安装 Chromium 或维护独立 HTML 模板。原生接口先尝试在线服务，报告内容会发送到配置的转图端点；失败时使用 AstrBot 本地渲染，效果和语法支持取决于框架版本。插件不按固定章节重排报告。

图片失败时发送完整 UTF-8 Markdown 文件，平台明确拒绝文件大小时再尝试 ZIP；不发送报告链接、不拆分正文。同会话交付按顺序进行，最多 8 个任务，渲染并发为 1，图片间隔至少 1 秒。渲染等待 60 秒，图片发送等待 120 秒，文件发送等待 300 秒。原生输出超过 2400 万像素时交付 Markdown；该检查发生在原生渲染之后，不限制框架生成图片时的峰值内存。文件也失败时会提示检查日志或重试。

PNG 超过 3 MiB 或高度超过 10000 px 时，发送前在线程中尝试转为 JPEG q92；仅在更小时使用，压缩失败则发送原图，原始 PNG 仍保留在报告存储中。日志会记录原始与发送字节数、是否压缩、分析耗时和后台恢复结果。大图上传明显变慢时可先查看这些日志。

分析默认等待 150 秒。AstrBot 的 `agent_runner.config.misc.tool_call_timeout` 建议至少 180 秒（旧版为 `provider_settings.tool_call_timeout`）；插件配置与工具时限扣除 15 秒余量后取较小值，流程另预留 5 秒收尾。股票/指数等待超时会提示转入后台，每 5 秒查询本地报告库，最多再等待 120 秒；只补发请求开始后（允许 2 秒时钟误差）生成的报告，不重新调用分析。黄金不查询股票报告库。停用插件会取消恢复任务。

插件内置最早的完整 Noto Sans CJK SC Regular 作为离线托底，不再附带两份大型衍生字体。初始化后台任务先补齐缺失字体，托底时用同一份 Regular 兼任常规体和粗体，粗体外观暂时为普通字重，脚注上标回退为 `[数字]`，单位上标保留。已有修复版、自定义字体及符号链接不覆盖。

完整 Stock Robot CJK Regular / Bold 下载顺序为 ghfast → jsDelivr → GitHub 直连，均固定同一提交并校验 SHA-256、可加载性、中文及全部上标数字。前两者是国内网络实测可达的镜像/CDN，并不保证位于境内。每次尝试最多 30 秒，连接和单次读取最多 15 秒；两个字重及全部来源合计最多 120 秒，单文件上限 20 MiB。超时、HTTP 错误或内容校验失败切换下一来源。下载失败清理临时文件、继续使用托底或已有字体，下次加载重试。网络调用复用现有 httpx 依赖并遵循其环境代理设置。

当前版本字体已安装时直接离线复用，不联网。自定义字体和符号链接不覆盖；已知旧字体先备份为带原 SHA-256 的 `.bak` 文件再升级。两份下载全部校验通过后才开始安装，但安装过程并非两文件事务；某一字重安装失败时会记录警告，下次加载补齐。字体影响 AstrBot 共享的本地字生图；首次新增或升级后请重启 AstrBot 清除已有缓存，重启前脚注用 `[数字]` 回退，上标单位不变。无可用中文常规体或粗体时跳过图片，直接交付完整 Markdown 文件。自定义字体的检查仅覆盖常用中文样本，不保证全部生僻字和其他语言。

字体保留完整字库和既有角标修复，不做子集化、不安装系统字体、不修改 AstrBot 核心。要求数据目录可写并支持同目录硬链接。Docker 应持久化 AstrBot 数据目录；卸载插件不删除共享字体或备份。托底安装约占 31.35 MiB，两份修复版已安装字体约占 31.88 MiB，首次下载额外临时占用约 31.88 MiB，旧字体备份另计。

开发测试资源不进入发布包。先执行 `python scripts/prepare_font_fixtures.py`，将固定版本且经过哈希校验的开发字体放入忽略目录 `.cache/font-fixtures/`，再运行字体测试；未准备资源时真实字体测试会跳过。许可证、固定哈希和重建说明见 `assets/fonts/`。

## 健康检查正常，但分析接口不可用

`/health` 的 `status=ok` 只说明服务能响应，还需核对同一地址返回的 `version` 是否与插件绑定值一致。绑定值见 `main.py` 的 `MANAGED_RELEASE_TAG`，版本更新记录见[更新日志](../CHANGELOG.md)。

启动器只能自动回收可确认由自己创建的旧进程，再进入受管升级流程；版本未知或无法确认进程归属时会报错，不擅自终止进程。排查时先确认实例、启动环境和进程归属，保留配置与报告，再停止旧服务并重载股票插件。

版本一致后再区分目录未加载、未收录、名称歧义与行情失败，不要将这些情况一律归为升级失败，也不要替换为 ETF 或成分股。
