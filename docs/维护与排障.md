# 维护与排障

本页面向需要手动启动、升级、清理或排查字体的用户；日常安装、聊天使用和基础配置见 [README](../README.md)。

## 自动准备与服务生命周期

插件默认安装当前绑定的内置分析服务 Stock Robot 版本（`main.py` 的 `MANAGED_RELEASE_TAG`，具体版本见[更新日志](../CHANGELOG.md)），不追随开发分支或自动选择 latest。服务由插件在 AstrBot 所在环境自动准备，固定连接 `127.0.0.1`，只需按需更换端口。

首次准备包括：

1. 下载插件绑定的已验证版本源码
2. 创建独立环境
3. 安装锁定依赖
4. 检查程序
5. 启动分析服务

AstrBot 主日志和插件数据目录的 `service.log` 会记录 `[1/5]` 至 `[5/5]` 阶段；序号表示当前阶段，各阶段耗时不同，不代表完成百分比。准备期间每 30 秒记录总耗时及最近一条脱敏输出；没有新输出也会说明正在等待。

插件会复用同一端口上健康的已有分析服务；停用插件不会关闭仅复用的服务。插件自己创建的服务在停用时回收。自建进程仍存活但健康检查失败时，先查看日志诊断，不会自动杀掉该进程并反复重启。

需要手动启动时，进入已安装 Stock Robot 的目录后运行，例如 Windows PowerShell：

```powershell
./.venv/Scripts/stock-robot.exe run --host 127.0.0.1 --port 25618
```

旧配置迁移只自动处理本地 HTTP 地址并保留端口；旧远程、带路径或 HTTPS 地址会明确提示人工处理，避免误建另一份实例。迁移前建议保留一份配置备份。旧配置明确关闭清理或自定义过安装时限的，保留原值；自动准备开关不再提供，旧关闭值不再生效。

**Docker 部署注意：** `127.0.0.1` 指向 AstrBot 容器自身，不是宿主机或其他容器。本插件不提供远程或跨容器地址配置，请确保插件数据目录已持久化。

安装优先使用 uv，否则使用 Python venv/pip；依赖按带哈希的锁清单安装。新安装只装核心依赖，旧就绪 RAG 环境保留，不自动卸载旧包。来源标签、查询渠道和下载摘要记录在 `instance/src/.bootstrap-source.json` 与安装状态文件中；下载摘要是实际内容的记录，不代表发布方签名验证。

## 升级与数据保留

插件与 Stock Robot 服务分别更新。默认情况下，插件升级会在后台把它自己在本机回环地址创建、且未使用自定义源码的服务升级至该插件已验证的绑定版本。候选源码与依赖完成自检后才切换，失败会保留上一版本；配置、报告与缓存不受影响。

自动安装的数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_stock_robot/`：

| 路径 | 内容 |
| --- | --- |
| `service.log` | 安装与服务启动日志 |
| `delivery_tmp/` | 报告交付副本及任务元数据 |
| `delivery_diagnostics/` | 不含报告全文的简要任务诊断 |
| `instance/.stock_robot/` | 模型配置、凭据、缓存与运行日志 |
| `instance/reports/` | 已生成的报告 |
| `instance/src/` | Stock Robot 源码 |
| `instance/venv/` | 独立 Python 环境 |
| `instance/install-state.json` | 安装状态记录 |
| `instance/.releases/` | 固定路径中的新版源码与独立环境 |
| `instance/active-runtime.json` | 活动版本及上一版本指针 |
| `waiting.sqlite3` | 会话等待队列及尚未完成的任务状态 |

需要主动重装自动安装的服务时：

1. 停用插件，确认插件创建的服务进程已退出，并备份插件数据目录。
2. 移除安装产物：`instance/src/`、`instance/venv/`、`instance/install-state.json`，以及存在时的 `instance/.releases/`、`instance/active-runtime.json`。这些路径仅在停用且备份后处理。
3. 保留 `instance/.stock_robot/` 与 `instance/reports/`，重新启用插件。

新安装仅使用插件声明已验证的绑定版本与核心依赖。自定义源码与可选依赖入口不再提供；旧自定义来源明确提示人工迁移，不自动替换。已经就绪的旧 RAG 环境保留依赖集，不自动卸载。配置目录包含 API Key，分享日志或备份时请隐去凭据。

## 升级期间的等待请求

服务暂不可用时，每个会话（群聊所有成员共享）最多保留最新三个不同标的，重复代码合并；超出时告知被替换的标的。恢复后 AI 统一询问是否继续，任意群成员均可明确确认，由 AI 理解并调用受校验的确认工具。确认前不会分析。

首次询问送达后等待 30 分钟；无人确认则最后提醒一次并清空。期间同一会话提出新的分析请求，会清空旧等待队列并正常处理新请求；普通聊天不清空。

确认后依次处理。恢复投递使用该会话当前模型生成自然衔接，不读取或写入完整聊天历史；AI 文案生成或发送失败时不会发送研报。异常最多尝试三次，间隔 30 秒，单次 AI 生成与文字发送合计最多 30 秒；报告已生成后重试不会重新分析。失败报告与诊断保留 72 小时。

队列和已生成报告的投递进度可跨重载恢复。若进程在分析请求发出后、结果保存前中断，由于服务接口无幂等请求号，该项停止自动重跑并保留诊断，避免重复分析。消息平台还须支持主动发送；这些能力须在实际平台验收。

## 磁盘清理与报告保留

插件会自动保留完整 Markdown 和有效 PNG 副本：成功交付保留 24 小时，渲染或发送失败保留 72 小时；图片失败但文件成功、取消和异常退出均按失败处理。期限从任务结束计算，异常退出从下次恢复检查计算，用户可在保留期内复制保存。ZIP 仅用于上传，上传结束即回收。

已结束任务产物预算为 256 MiB：先清理到期产物，仍超限淘汰最旧任务。期限是上限，容量压力下可能提前删除。任务元数据计入产物预算；未知内容或无法验证归属的旧目录保留并提示，不会为了达标盲删。活动任务和上传中的文件不参与淘汰。

简要诊断保留 7 天，预算 16 MiB，记录阶段、耗时、错误类别和清理原因，不复制报告全文或凭据。每次报告交付任务对应一份诊断。安装和运行共用 `service.log`，每份 10 MiB、最多 5 份（含当前文件），历史日志最多保留 7 天；已有超大日志只保留预算内尾部。清理在初始化、每 10 分钟和新任务开始前执行，也在交付结束后检查产物预算。

`cleanup_previous_reports` 新安装默认开启，已有显式关闭值保留，修改后重载生效。开启后仅清理插件持有且经过安装来源与报告布局验证的自建服务中超过 7 天的股票/指数 Markdown 原始报告，以修改时间计算。当前识别已验证的 Stock Robot 绑定版本报告保存实现；旧版本或保存实现变化时跳过并提示，未知文件不删除。外部或仅健康复用的服务、活动任务、安装中及分析超时/失败后状态不明时跳过。分析状态不明后本次插件生命周期保持保守，重载并回收原自建进程后才能重新建立归属。

原始报告没有容量淘汰规则，不删除回测、雷达、会话、配置、数据库、依赖环境、字体和用户副本。该互斥只能保护插件请求：自建服务如果也供 Web、定时订阅或其他客户端使用，应保持原始报告清理关闭。多实例无法取得报告独占锁时跳过留存和删除，继续交付。

本功能不新增第三方依赖或系统服务。产物、诊断和插件日志预算合计约 322 MiB，活动任务、服务原始报告和依赖占用另算，不是整个插件或主机的硬容量限制。写盘或删除失败会记录警告并继续服务，磁盘完全耗尽时仍可能导致文件上传失败。

## 报告图片与字体

报告通过 AstrBot 原生字生图生成，不安装 Chromium 或维护独立 HTML 模板。原生接口先尝试在线服务，报告内容会发送到配置的转图端点；失败时使用 AstrBot 本地渲染，效果和语法支持取决于框架版本。插件不按固定章节重排报告。

图片失败时发送完整 UTF-8 Markdown 文件，平台明确拒绝文件大小时再尝试 ZIP；不发送报告链接、不拆分正文。同会话交付按顺序进行，最多 8 个任务，渲染并发为 1，图片间隔至少 1 秒。渲染与图片发送分别等待 60 秒，文件发送等待 300 秒。原生输出超过 2400 万像素时交付 Markdown；该检查发生在原生渲染之后，不限制框架生成图片时的峰值内存。文件也失败时会提示检查日志或重试。

插件附带 Noto Sans CJK SC Regular 与 OFL 许可证，字体原始大小 16,437,364 字节（约 15.68 MiB）。启用时通过 AstrBot 的数据目录 API 定位 `font.ttf`，仅在不存在时新增，绝不覆盖已有文件；不运行时下载字体、不安装系统字体、不修改 AstrBot 核心。适用于 Windows、Linux 和 Docker，要求数据目录可写且文件系统支持同目录硬链接；安装失败只记录警告，不阻止插件加载。

已有文件会验证可加载性与常用中文样本字符映射，缺字、损坏或无法检查时提示路径和处理建议。检查不保证所有中文、生僻字或其他语言覆盖。此字体影响所有使用 AstrBot 原生本地字生图的插件，英文外观也可能变化，不能提供逐字符字体回退或所有语言支持。若框架已有字体缓存，安装后需手动重启 AstrBot；插件不清除全局缓存、不自动重启。

Docker 中应持久化 AstrBot 数据目录；字体不是放在容器系统字体目录。Windows/Linux 使用各自的实际数据目录，无硬编码容器路径。升级插件不会覆盖已有字体，卸载插件也不会自动删除共享的 `font.ttf`。需要更换时请先备份，手工替换并重启。具体字重和字体入口兼容性取决于 AstrBot 版本；Regular 不能保证旧版本独立加载的粗体、斜体也支持中文。

## 安装来源与版本

- 默认安装插件绑定且已验证的主仓版本，不追随开发分支或自动选择 latest。
- 配置文件中的 `base_url`、`bootstrap_extras` 和 `source_archive_url` 仅保留为隐藏迁移信息，不是新用户选项；框架不会在插件检查前丢弃这些旧值。
- 安装优先使用 uv，否则使用 Python venv/pip；依赖按带哈希的锁清单安装。新安装只装核心依赖，旧就绪 RAG 环境保留，不自动卸载旧包。
- 来源标签、查询渠道和下载摘要记录在 `instance/src/.bootstrap-source.json` 与安装状态文件中。下载摘要是实际内容的记录，不代表发布方签名验证。
- 插件停用时会回收自己创建的服务，保留配置与报告；复用的外部服务不会被关闭。自建进程仍存活但健康检查失败时，应先查看日志诊断，不会自动杀掉该进程并反复重启。
