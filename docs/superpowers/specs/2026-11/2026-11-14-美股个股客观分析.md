## 1. 目标与边界

在现有 `analyze_stock` 工具内支持美股个股，默认交付**客观数据研报**：行情、技术面、估值、财务、新闻，逐项标注来源、日期与缺失原因，报告继续以图片发送。

本期包含：

- 美股普通股与 ADR（ADR 按普通股处理，数据覆盖以主仓数据源为准），例如 `AAPL`、`MSFT`、`TSLA`、`BABA`、`BRK.B`
- 输入 `AAPL`、`AAPL.US`、`aapl` 统一为 `AAPL`；类别股 `BRK.B` 保留点号，`BRK-B` 归一为 `BRK.B`
- 与 A 股/港股相同的客观数据模式：`analysis.extra_enabled=false` 时不请求评分、信号和 AI

本期不包含：

- 行业同行对比：没有免费、稳定的美股行业池；行业维度标记“不适用”，不计入覆盖率
- 五维综合评分、规则信号、仓位建议：即使全局开启额外分析，美股也不评分、不生成信号；允许基于真实事实的 AI 解读（不评分）
- ETF/基金、期权、做空数据、盘前盘后价作为“当前价”、汇率换算、回测/推送/雷达/订阅
- 美股指数：指数侧已有 `SPX/IXIC/DJI` 能力，不在本期入口范围
- 类别股完整财报：东财 F10 对 `BRK.B` 返回失败（见第 8 节），行情/估值/新闻可用，财务维度显示不可用原因

## 2. 仓库分工

| 层 | 仓库 | 工作 |
| --- | --- | --- |
| 分析引擎 | `stock_robot` | 市场识别、取数、分析、报告、HTTP/CLI/Agent、测试 |
| 聊天入口 | `astrbot_plugin_stock_robot` | 工具描述、代码规范化、422 文案、文档、服务版本绑定 |

插件不实现行情、财务或估值逻辑，只转发 `/api/v1/analyze` 并交付报告。因此主仓必须先发布支持美股正式版，插件再升级 `MANAGED_RELEASE_TAG`。

## 3. 代码与市场识别

- 新增 `is_us_symbol` 与 `validate_analyze_symbol`；保持 `validate_symbol` 的 A 股/港股语义不变，避免回测、订阅、雷达把美股误送入 A 股链路。
- 识别顺序：港股（5 位数字、`.HK`、`hk` 前缀）→ A 股（6 位数字）→ 美股（字母代码）。纯数字永不识别为美股。
- 标准化：
  - 去空格、转大写、去 `.US` 后缀
  - 单字母类别股 `BRK-B` → `BRK.B`
  - 保留 `BRK.B`、`BF.B` 的点号
- 格式校验：`^[A-Z][A-Z0-9]{0,9}(?:[.-][A-Z0-9]{1,2})?$`，长度不超过 12；拒绝空值、纯数字、含 `_` 或空格的输入。
- `symbol_market` 返回 `us`；`normalize_symbol` 对美股返回标准代码；`resolve_name_result` 增加美股分支（见 4.5）。
- 报告目录：`reports/stock/<代码>/<YYYY-MM>/<代码>_<时间>.md`；股票代码正则扩展到 `\d{6}`、`\d{5}.HK`、美股代码三选一。
- 旧版扁平目录清理仍只认 `\d{6}`/`\d{5}.HK`，不把报告根目录下的字母目录当作旧报告。

## 4. 数据层

### 4.1 行情

- 主源：`ak.stock_us_daily(symbol=<代码>, adjust="qfq")`（新浪美股，前复权），取最近一年，最少 60 个交易日。
- 备源：`ak.stock_us_hist(symbol="105.<代码>", ...)`（东方财富，需 `105/106/107` secid）。该接口本机探针出现 `ConnectionError`，只作可选回退，不作为唯一依赖。
- 校验：`date/open/high/low/close/volume` 齐全；`low ≤ min(open, close) ≤ max(open, close) ≤ high`；价格 > 0；成交量 ≥ 0；同日冲突拒收整段来源；坏行隔离。
- 复权：统一前复权并在报告披露；不使用盘前盘后价。
- 当前价：取最后交易日收盘价，标注“截至 <日期>”；`current_quote` 报价链路保持 A 股专用，美股不请求盘后报价。
- 少于 20 条有效行情时不生成个股报告，API 返回 422 “未取得足够的该美股行情，请核对代码或稍后重试”（见第 7 节）。

### 4.2 财务

- 主源：东财美股 F10，`stock_financial_us_report_em` 三大报表（`单季报`）+ `stock_financial_us_analysis_indicator_em`（`单季报`/`年报` 指标）。
- 科目映射沿用港股同码：

| 字段 | STD_ITEM_CODE |
| --- | --- |
| 营业收入 | `004001999` |
| 归母净利润 | `004015999`（缺失回退 `004013999`） |
| 总资产 | `004005999` |
| 归母权益 | `004013999` |
| 股东权益合计 | `004017999` |
| 经营现金流 | `003999` |
| 购建固定资产 | `005002` |
| 基本每股收益 | `004017003` |
| 加权平均股数 | `004017007` |

- 口径字段：`period_basis="single"`、`period_start=START_DATE`、`reporting_basis="US GAAP"`、`report_currency="USD"`、`amount_currency_verified=True`、`cash_flow_basis="reported"`。
- **报告期归一**：`fiscal_quarter` 取 `REPORT_DATE` 所在月月末（如 `2026-09-26` → `2026-09-30`），用于跨年同比精确匹配；源报告日写入 `financial_selection_note`。这样可覆盖 AAPL/COST 等 52/53 周财年公司；无法匹配同期时只显示“同期样本不足”，不猜。
- TTM：最近四个单季合计，显式按 `period_basis="single"` 求和，不复用累计去累积启发式；报告注明“最近四个财季合计”。
- 指标：ROE 优先取 `ROE_AVG`；缺失时按 TTM 净利 / 期末归母权益派生，并在 `field_sources` 标注；毛利率取 `GROSS_PROFIT_RATIO`；银行/保险缺毛利率时不补造。
- 覆盖：至少 4 个单季；不足 4 期时财务维度 partial。`BRK.B` 等 F10 失败标的返回空数据并保留失败原因。
- 缓存：沿用现有 legacy 路径与 `financial` 季度 TTL；缓存键含标准代码。

### 4.3 估值

- 主源：直连百度 `https://finance.baidu.com/opendata`，参数 `market=us`、`code=<代码>`、`query=市盈率(TTM)|市净率`、`chart_select=近一年`；使用 `requests` 并带超时，不使用无 UA 的 akshare 封装。
- 快照：分别取 PE/PB 曲线末值与日期；`pe_as_of`/`pb_as_of` 独立记录；无共同日期时保留较新一项并说明。
- 历史分位：至少 120 个有效样本才计算；报告展示区间、样本数、中位数/最低/最高；历史低分位不等于低风险。
- PS：百度不提供 PS 口径；用新浪美股快照总市值 ÷ 东财 TTM 营业收入派生，`ps_source="新浪美股快照市值与东财TTM营收派生"`、`ps_as_of=快照日期`；仅披露，不计分；任一输入缺失则不派生。
- 校验：百度 `result.code` 必须与代码一致；日期不晚于采集日；数值为正有限数；失败写入 `failed_components` 与诊断，不伪造。
- 不提供行业溢价、同行对比。

### 4.4 新闻

- 复用主仓 `data/hk_news.search_news`（东财关键词检索，`curl_cffi` 客户端），单关键词单请求、不翻页。
- 查询词：中文公司名（如 `微软`）+ 代码（如 `MSFT`），最多两并发；近 30 天；最多 20 条；标题/日期/来源/链接/摘要。
- 输出 `NewsData.headlines` + `_raw_sentiment`（`RawSentimentItem`），走现有客观模式新闻展示；不做情绪评分。
- 相关性限制：关键词检索可能包含间接报道；报告注明“仅关键词检索参考，不保证完整覆盖近 30 天”。

### 4.5 名称与报价

- 名称：新浪 `https://hq.sinajs.cn/list=gb_<代码小写>`，解析中文名；失败回退东财指标 `SECURITY_NAME_ABBR`；再回退代码。
- 新浪快照同时返回价格、涨跌幅、总市值、52 周高低、盘后字段；本期**只用名称与总市值**，价格以日线收盘为准。
- `BRK.B` 的新浪快照为空，名称回退代码；行情与百度估值仍可用。

### 4.6 采集记录与降级

- 每个维度写 `DataCollectionRecord`（来源、采集时间、缓存状态、失败原因）；主源/备源失败原因都保留。
- 不新增数据库或迁移；沿用 `cache.db`、7 天报告清理与现有断路器。
- 行业维度不发起采集，直接写 `not_applicable` 记录。

## 5. 分析层

- 财务：输出 USD/美国会计准则/单季口径说明；TTM 为四单季合计；同比仅在同期匹配时生成；ROE 派生时标注来源。
- 技术：复用 MA5/20/60、量比、MACD；前复权；不新增指标。
- 估值：当前 PE/PB/PS、近一年分位（样本 ≥120）、来源/日期/样本；PS 派生说明；不输出行业溢价。
- 行业：标记不适用；报告显示“不适用：本期美股不提供行业同行对比，不计入覆盖率”；不参与覆盖率、评分与 AI 结论。
- 舆情：新闻参考，`score=None`；不参与评分。
- 评分/信号：美股 `score=None`、`has_scored_data=False`、`signal_allowed=False`；不加载 A 股评分模板（`ConfigLoader.load_for_context` 对 `us` 返回 `None`）。
- AI：仅当全局额外分析开启且存在真实事实时生成不评分解读；新增 `batch_analysis_us.jinja2`，提示词禁止编造、评分和交易建议。

## 6. 报告与数据质量

- 市场标签“美股”。
- 免责声明新增：美元计价、美国会计准则、财年差异、盘前盘后与数据延迟、不换汇、免费数据源限制。
- 覆盖率：适用维度 = 财务/技术/估值/舆情，按 30/20/25/5 归一为 100%；行业不适用，不计分母。
- 数据覆盖表：行业行状态“不适用”并附原因；其余维度展示样本范围、来源、数据截止、缓存状态与缺失原因。
- 综合评分区：“不适用：美股本期不提供综合评分与规则信号”；模型信号区同。
- Web payload：`analysis_mode`、`market="us"`、`score` 空、`signal` 空、`data_quality` 与 Markdown 同源。
- 前端 `report-renderer.js` 增加美股分支：财务口径说明、行业不适用、评分/信号不适用。

## 7. 接口与入口

- `POST /api/v1/analyze`：接受美股代码；名称解析；市场 `us`；少于 20 条有效行情时返回 422 “未取得足够的该美股行情，请核对代码或稍后重试”，其余维度失败仍生成 partial 报告。
- CLI `analyze`：接受美股代码；错误提示覆盖三市场；`--with-market` 对美股不嵌入 A 股大盘环境。
- Agent `analyze_stock`：描述与参数说明加入美股代码示例；复用 `normalize_symbol`/`symbol_market`。
- 报告保存/库/清理：`report/formatter.py` 股票代码正则、`maintenance/report_retention.py` 新布局正则、`api/report_library.py` 保持路径解析。
- 订阅/回测/雷达：不纳入美股；继续使用 A 股/港股校验与提示。

## 9. 非目标、风险与待确认

- 数据源均为免费、非官方接口，可能限流、改版或延迟；不承诺 SLA。东财 push2 在本机高度不稳定。
- 百度曲线是日历交易日序列，需与行情日期取交集；不保证覆盖上市以来完整历史。
- 52/53 周财年按月末归一，可能与公司官方财季标签相差数日；报告需披露。
- 类别股（`BRK.B`）财务不可用；ADR 的 F10 覆盖未逐一验证，缺失时如实披露。
- 新闻是关键词检索参考，相关性有限，不作情绪评分。
- PS 为派生值，仅披露；不参与任何判断。
- 美股不提供行业对比、评分和信号；开启额外分析时也不改变这一边界。
- 名称解析依赖新浪快照，失败时退回代码；不把盘后价当收盘价。

## 10. 验收标准

- 主仓：CLI、HTTP、Web 三个入口对 `AAPL`、`MSFT`、`BRK.B` 均生成报告；行情/财务/估值/新闻四维有来源、日期与样本；行业显示不适用且不计覆盖率；无综合评分与模型信号。
- 主仓：`AAPL` 与 `MSFT` 财务至少 4 个单季并给出 TTM；`BRK.B` 财务不可用但报告仍生成；新闻至少 3 条或明确失败原因。
