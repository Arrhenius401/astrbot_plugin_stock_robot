# 港股指数身份兼容修复设计（v0.4.1 + 插件 1.3.1）

- 日期：2026-11-17
- 状态：已实施并通过本地验收；主仓 v0.4.1 已正式发布，插件 1.3.1 待发布
- 范围：插件 `astrbot_plugin_stock_robot` + 内置分析服务 `stock_robot`（下称主仓）
- 依据：插件 `9caa605`、主仓 v0.4.0 标签（`44e6abf`）、恒生官方指数元数据实测（773 条，其中 `regionId=hongkong` 560 条）、此前的真实服务验收记录
- 关联计划：[港股指数身份兼容修复实施计划](../../plans/2026-11/2026-11-17-港股指数身份兼容修复.md)

## 0. 结论

采用“服务目录加别名 + 插件格式归一和解析编排”的路线：

1. 主仓发布 **v0.4.1**：从恒生官方元数据 `indexShortName` 自动生成官方别名，新增 `GET /api/v1/indices/resolve`，由服务做归一化、精确匹配、版本策略和歧义判断。
2. 插件发布 **1.3.1**，绑定 v0.4.1：只做格式归一、调用 resolve、刷新控制、队列/报告编排和错误反馈；不再维护官方别名表，不再硬编码 `HSTECH -> HSI:02083.00`。
3. 不做口语同义词表。`恒科`、`恒指`、`科指`、`国指` 不在本版解析范围；如果真实日志出现这类参数，另行评估数据补充，不阻断本版。
4. 不再要求服务逐个指数接受别名；官方 short name 是数据，刷新时自动更新，新增指数不需要改代码。

## 1. 背景与根因

用户请求“分析恒生科技”时出现三类独立问题：

1. 模型把指数请求替换为 `513130`，进入个股分析流程。
2. 插件收到 `HSTECH.HK`，原样查询目录失败；`恒科` 也未归一。
3. 全新部署没有港股目录缓存时，HSTECH 不在 v0.4.0 内置目录中，首次使用失败。

已确认：

- `pending_queue.canonical_symbol` 的指数别名只有 `恒生科技 -> HSTECH`、`HSI:02083.00 -> HSTECH` 等少数映射；`HSTECH.HK`、`恒科` 未转换。
- `client.resolve_index` 只把归一化后的 `HSTECH` 转成官方身份 `HSI:02083.00` 再查询；`HSTECH.HK` 原样查询，因此即使目录已有恒科也查不到。
- v0.4.0 的内置 `index_mapping.csv` 只有 `HSI`、`HSCEI`，没有 HSTECH；HSTECH 依赖 HSI 官方目录快照。
- 主仓 v0.4.0 已提供 `POST /api/v1/indices/refresh?source=hsi`；`sync_catalog(refresh=True)` 成功返回 `live`，失败保留旧快照并返回 `stale`；`IndexMapping()` 每次请求重新加载，刷新后下一次查询可见。
- 恒生官方元数据中 560 条港股指数均有非空且当前唯一的 `indexShortName`，例如 `HSTECH`、`HSTECH TRI`、`HSTECH NTRI`、`HSHDYI`、`HSML100`；v0.4.0 的 `parse_hsi_catalog` 没有保留该字段，`IndexMappingEntry.aliases` 为空。这是需要插件硬编码 HSTECH 的根因。

聊天模型后来推断“没有收录恒科，只能看成分股”，只是对第 2 类错误的二次推断，不是真实原因。

## 2. 目标与非目标

### 目标

1. `HSTECH`、`HSTECH.HK`、`恒生科技`、`HSI:02083.00` 等写法解析到同一官方价格身份。
2. 官方 short name 全量数据驱动：`HSHDYI`、`HSML100`、`HSTECH TRI`、`HSTECH NTRI` 等无需逐个写别名。
3. 全新部署或旧快照无别名时，首次指数查询自动准备目录并完成分析。
4. 目录不可用、刷新失败、刷新后仍未收录、名称歧义、身份已确认但行情失败，分别准确反馈。
5. 插件只做格式归一和编排；身份判定归服务目录。

### 非目标

- 不支持 `恒科`、`恒指`、`科指`、`国指` 等口语同义词的直接解析。
- 不承诺全部港股指数都能生成报告；目录收录、真实行情可取得、数据完整是三件事。
- 不开放美股指数。
- 不分析 ETF 自身表现，不用指数报告替代 ETF。
- 不自动把指数请求改路由成 ETF/成分股，反之亦然。
- 不修改行情、估值、报告生成管道。

## 3. 职责划分

| 层 | 职责 |
| --- | --- |
| LLM | 选对工具；优先传官方指数名称/代码；不追加市场后缀、不猜代码、不替代标的 |
| 插件 | 格式归一；调用 resolve；处理成功/歧义/未收录；刷新控制；队列/报告编排；错误反馈；工具误用纠正 |
| 服务 | 官方别名数据；文本归一；目录解析；版本/歧义策略；返回官方身份和目录状态 |

原则：Prompt 负责行为，服务负责身份，插件负责编排。Prompt 不能替代确定性解析。

## 4. 服务 v0.4.1 设计

### 4.1 官方别名入库

- `parse_hsi_catalog` 读取 `indexShortName`，过滤 `regionId=hongkong`。
- 当前 560 条港股记录的 short name 非空且唯一；未来出现空值或重复时按“无别名/歧义”处理，不静默选择。
- `IndexMappingEntry.aliases` 写入官方 short name，例如：
  - `HSI:02083.00` → `("HSTECH",)`，`return_type=price`
  - `HSI:12083.00` → `("HSTECH TRI",)`，`return_type=gross_total_return`
  - `HSI:22083.00` → `("HSTECH NTRI",)`，`return_type=net_total_return`
- 同时保留官方 `indexSeriesCode`，写入 `IndexMappingEntry.series_code`；价格/TRI/NTRI 共用同一 series code（如 `hstech`），用于把同一指数的收益版本归为一个 family。`series_code` 缺失时回退基名分组。
- 不做口语同义词表；`恒科` 不在服务别名数据中。
- 不按指数写解析分支；别名只作为目录数据参与通用匹配。

### 4.2 快照与回滚兼容

- 主快照 `index-catalog-hsi.json` 保持 v0.4.0 可读的字段结构，不新增必填字段。
- 官方 short name 写入独立侧车文件，例如 `index-catalog-hsi.aliases.json`，按官方 identity 映射到 aliases。
- v0.4.1 同时读取主快照和侧车；v0.4.0 忽略侧车，仍能读取主快照，从 v0.4.1 回滚到 v0.4.0 不会导致整份目录失效。
- 侧车缺失、损坏、或 identity 集合与主快照不一致时：
  - 不阻止服务启动；
  - 该来源的 aliases 视为未加载；
  - resolve 返回 `hsi_aliases_loaded=false`，由插件触发一次刷新。
- 主快照和侧车均使用原子替换；刷新失败保留旧文件。
- 如果 `CatalogEntry` 为承载 short name 增加默认字段，主快照序列化时必须剔除该字段；建议用独立别名结构或自定义序列化，避免改变主快照 schema。

### 4.3 通用归一化

服务侧统一处理，不按指数写分支：

- NFKC；去首尾空白；压缩连续空白；ASCII 大写。
- 统一 `：` → `:`、`．` → `.`、`－`/`—` → `-`。
- 匹配时忽略空格、连字符、下划线的差异：`HSTECH-TRI` 与 `HSTECH TRI` 等价。
- 指数命名空间允许剥离尾部市场后缀：`.HK`、`.SH`、`.SZ`、`.US`、`.INDEX`。
- 不剥离 `.00` 这类收益版本后缀；`HSI:02083.00` 保持完整。
- 官方 HSI 代码：`HSI:2083.00` 补零为 `HSI:02083.00`；`HSI:02083` 生成 `HSI:02083.00` 候选，由目录确认。
- A 股指数：`sh000300`、`000300.SH` → `000300`；六位数字保持。
- 五位港股个股代码不按指数处理；由插件的指数工具校验拒绝。
- 归一化仅用于匹配；报告和显示使用目录中的官方名称。

### 4.4 解析与版本策略

解析必须分匹配质量层，不能把“子串命中多个收益版本”直接判为歧义。

1. 归一化查询。
2. 精确匹配 symbol / identity / name / aliases。命中一个直接返回；多个进入 version family 处理。
3. 基名精确匹配（base-name exact）：
   - 对查询和候选名称去掉尾部收益版本限定词（总股息累计指数、净股息累计指数、股息累计指数、总收益、全收益、净收益、收益、价格等）和尾部通用“指数”，再压缩空白/标点；重复直到稳定。
   - 只保留基名与查询基名完全相等的候选。
   - 归一化后的原始查询长度小于 3 时不使用本层，避免“恒生”这类过宽词直接命中恒生指数。
   - 这一层优先于普通子串匹配；基名精确命中后，不再把更低层的子串结果拉进来制造歧义。
4. 普通子串匹配：归一化查询包含在归一化 symbol / name / aliases 中。
5. 对候选按 version family 分组：
   - 优先 `(provider, series_code)`；HSI 的价格/TRI/NTRI 共用 `indexSeriesCode`（如 `hstech`），属于同一 family。
   - `series_code` 缺失时回退 `(provider, market, base_name)`。
   - 旧 CSV 的 HSI/HSCEI 价格条目先用现有 `legacy_hk`/`price_symbol` 与官方价格条目去重，避免同一价格指数被当成两个 family。
6. 若命中多个 family，返回歧义；若只有一个 family，在该 family 内做版本选择：
   - 查询含价格词（价格/PRICE/PI）→ `price`；
   - 含总收益词（总收益/全收益/总股息累计/TRI/TOTAL RETURN/GROSS）→ `gross_total_return`；
   - 含净收益词（净收益/净股息累计/NTRI/NET TOTAL RETURN/NET）→ `net_total_return`；
   - 单独“收益”不作为毛/净方向，视为版本不明确；family 有多版本时歧义；
   - 未指定版本 → 若 family 内只有一个 `price` 条目，选价格；若只有一个条目，选它；否则歧义；
   - 指定版本但无匹配条目 → `not_found`（收益版本未收录），不退回价格；
   - 同一版本仍有多个条目 → 歧义。
7. 返回目录中的官方身份，不返回插件构造的别名。

示例（通用规则，不是逐指数特判）：

| 查询 | 匹配层 | 结果 |
| --- | --- | --- |
| `HSTECH` | 精确 alias | 价格 `HSI:02083.00` |
| `HSTECH TRI` | 精确 alias | 毛收益 `HSI:12083.00` |
| `恒生科技指数` | 精确 name | 价格 |
| `恒生科技` | 基名精确：价格/TRI/NTRI 同 family | 价格 |
| `恒生科技总收益` | 基名精确 + 毛收益词 | 毛收益 |
| `恒生科技净收益` | 基名精确 + 净收益词 | 净收益 |
| `恒生科技收益` | 基名精确，但版本词不明确 | 歧义 |
| `恒生科技美股半导体` | 基名精确：该系列同 family | 价格 |
| `恒生科技美股` | 无基名精确；子串命中多个 family | 歧义 |
| `恒生` | 长度不足，基名层跳过；子串多个 family | 歧义 |

这样“恒生科技”不会被价格/TRI/NTRI 的子串多命中拖成歧义，而“恒生科技美股”这类真正跨系列的写法仍会要求用户选择。版本规则是通用的，不针对某个指数；`HSTECH` 精确命中价格别名，`HSTECH TRI` 精确命中毛收益，`HSTECH NTRI` 精确命中净收益，互不覆盖。

### 4.5 新增 resolve 接口

```text
GET /api/v1/indices/resolve?q=<原始或归一化查询>
```

所有解析结果使用 HTTP 200；空查询 422；服务内部异常 500/503。

成功：

```json
{
  "status": "ok",
  "query": "HSTECH.HK",
  "normalized": "HSTECH",
  "entry": {
    "symbol": "HSI:02083.00",
    "name": "恒生科技指数",
    "market": "hk",
    "provider": "hsi",
    "return_type": "price",
    "aliases": ["HSTECH"]
  },
  "catalog": {
    "hsi_loaded": true,
    "hsi_aliases_loaded": true,
    "hsi_updated_at": 1760000000.0
  }
}
```

歧义：

```json
{
  "status": "ambiguous",
  "query": "恒生科技收益",
  "candidates": [
    {"symbol": "HSI:12083.00", "name": "恒生科技指数(总股息累计指数)", "market": "hk", "return_type": "gross_total_return"},
    {"symbol": "HSI:22083.00", "name": "恒生科技指数(净股息累计指数)", "market": "hk", "return_type": "net_total_return"}
  ],
  "catalog": {
    "hsi_loaded": true,
    "hsi_aliases_loaded": true,
    "hsi_updated_at": 1760000000.0
  }
}
```

未收录：

```json
{
  "status": "not_found",
  "query": "某个写法",
  "catalog": {
    "hsi_loaded": false,
    "hsi_aliases_loaded": false,
    "hsi_updated_at": null
  }
}
```

字段约定：

- `catalog.hsi_loaded`：HSI 主快照存在且可解析。
- `catalog.hsi_aliases_loaded`：侧车别名存在、可解析，且 identity 集合与主快照一致。
- `catalog.hsi_updated_at`：主快照 mtime，epoch 秒；无快照为 null。
- `entry.aliases` 返回给插件做缓存/队列归并，不作为分析入参。
- `market` 仍返回 `us`/`unknown`；服务不替插件做产品限制，由插件决定是否可分析。
- resolve 是只读接口，不触发目录刷新。

### 4.6 刷新接口

复用现有：

```text
POST /api/v1/indices/refresh?source=hsi
```

- 成功：写入主快照 + 别名侧车，返回 `state=live`、`total`。
- fetch 失败但有旧快照：保留旧文件，返回 `state=stale`。
- 无旧快照且失败：返回 502。
- 服务端不做 TTL 判断；刷新由插件按目录状态控制。
- 刷新后下一次 `IndexMapping()` 能读到新主快照和新侧车。

### 4.7 服务侧测试

- short name 解析、空值、重复、版本字段、`indexSeriesCode` family。
- 侧车写入/读取/缺失/损坏/identity 不一致。
- 主快照序列化不含新字段，v0.4.0 可读。
- 归一化矩阵：大小写、全角、空格、标点、`.HK/.SH/.SZ`、`HSI:2083.00`、`HSI:02083`。
- resolve：精确别名、精确名称、代码、基名精确、子串、价格优先、TRI/NTRI、歧义、未收录。
- 基名/版本 family：`恒生科技` → 价格；`恒生科技总收益` → 毛收益；`恒生科技净收益` → 净收益；`恒生科技收益` → 歧义；`恒生科技美股` → 歧义；`恒生科技美股半导体` → 价格。
- 旧主快照 + 无侧车：`hsi_loaded=true`、`hsi_aliases_loaded=false`。
- 刷新成功/stale/失败/无快照。

## 5. 插件 1.3.1 设计

### 5.1 只做格式归一，不做身份映射

- 删除 `HSTECH -> HSI:02083.00` 硬编码。
- 删除官方别名表。
- 新增纯格式归一：
  - NFKC、大写、去空白、统一标点；
  - 剥离 `.HK/.SH/.SZ/.US/.INDEX`；
  - 官方 HSI 代码补零；
  - A 股六位补零。
- 归一化结果只用于发送给 resolve、队列提示和显示；不自行判断等价身份。
- `canonical_symbol` 的指数分支不再做别名映射；队列身份由 resolve 结果或归一化 query + 缓存决定。

### 5.2 解析编排

`analyze_index` 流程：

1. 格式归一原始参数。
2. 调用 `GET /api/v1/indices/resolve?q=...`。
3. `status=ok`：
   - 校验 `market in {a-shares, hk}`；
   - 美股 → “美股指数暂未开放”；
   - 未核验市场 → “市场尚未核验，暂不可分析”；
   - 通过则返回 `ResolvedIndex(symbol, name, market, return_type)`。
4. `status=ambiguous`：
   - 展示名称（代码，收益版本）；
   - 不分析、不刷新、不代选。
5. `status=not_found`：
   - 按目录状态决定是否刷新（见 5.3）；
   - 刷新后重新 resolve 一次；
   - 仍无结果 → 准确失败。
6. 网络/5xx/无效 JSON：
   - “指数目录服务暂不可用”；
   - 不刷新、不分析。

分析、报告查询、下载、补发都使用 `ResolvedIndex.symbol`，不再重新解析，避免迟到补发再次触发刷新。

### 5.3 刷新控制

只由 resolve 的 `catalog` 状态驱动，不用关键词猜“是不是港股”：

| 条件 | 行为 |
| --- | --- |
| `hsi_loaded=false` | 刷新一次 |
| `hsi_aliases_loaded=false` | 刷新一次（覆盖旧快照升级） |
| `hsi_updated_at` 早于 7 天 | 刷新一次 |
| 已加载、别名已加载、未过期 | 不刷新，直接报“目录未收录” |
| `status=ambiguous` | 不刷新 |
| `market=us/unknown` | 不刷新 |
| resolve 网络/5xx | 不刷新 |

参数：

- 每次请求最多 1 次刷新。
- 刷新超时 12 秒；剩余预算不足 20 秒则不刷新，返回“本次时间不足”。
- 成功后冷却 10 分钟；失败后冷却 60 秒（进程内）。
- 进程内 `asyncio.Lock` 单飞；等待者拿到锁后重新 resolve，不重复 POST。
- 刷新失败保留旧目录；不循环重试。
- 刷新 404/405 → “当前服务不支持目录解析/刷新，请升级至绑定版本”。
- 刷新超时 → “未在等待内完成，可能仍在后台更新”。
- 多进程下可能重复刷新；服务端原子写入保证不损坏，设计接受该边界。

### 5.4 队列与报告身份

- 入队时保存格式归一后的 query；如果本地已有 resolve 缓存，同时保存官方 symbol。
- 去重优先用官方 symbol；没有缓存时用归一化 query。
- 服务恢复、批量处理前，对每个目标调用 resolve；多个目标解析到同一官方 symbol 时合并，只分析一次。
- resolve 成功后把官方 symbol 写回队列记录；后续分析、报告查询、补发都用它。
- 本地缓存只存服务返回的 aliases/symbol，不存手写别名；缓存保存在插件数据目录。
- 冷启动无缓存时允许暂时按归一化 query 排队，服务可用后合并；不为了队列去重把官方别名写回代码。

### 5.5 工具说明与 Prompt

`analyze_index` 说明：

> 仅用于指数。用户询问指数走势、估值或表现时使用。
> 参数优先使用官方指数名称或代码；不要追加 `.HK`、`.US` 等市场后缀，不要猜测不存在的代码，不要用 ETF、成分股或其他指数替代。
> 无法确定官方名称/代码时传用户原词，由服务目录解析。
> 返回歧义时请用户选择具体代码，不要代选。
> 用户明确询问 ETF 自身表现时，不要用其跟踪指数的报告代替。
> 美股指数暂未开放。
> 失败原因原样转述，不得扩展为“指数不存在”或建议替代标的。

`analyze_stock` 说明：

> 仅用于个股。指数、ETF/基金请求不要使用本工具。
> 不得把指数替换为跟踪它的 ETF、成分股或其他个股。
> 用户询问 ETF 自身表现时，本工具不适用。
> 失败原因原样转述，不要用其他标的替代。

原则：Prompt 不要求模型“自己标准化成官方代码”，而是“优先官方名称/代码、不要加后缀/猜代码、无法确定传原词”；身份由 resolve 决定。Prompt 是行为约束，不是身份保证。

### 5.6 确定性误用纠正

在调用 `_run_analysis` 前拦截可证明的误用，只给模型纠正提示，不自动改路由，不先发用户错误：

| 工具 | 输入 | 处理 |
| --- | --- | --- |
| `analyze_stock` | 精确已知指数名称/官方短名/`HSI:` 代码/`HSTECH.HK` | “这是指数标识，未按个股分析；如用户问指数，请用指数工具并保留原词” |
| `analyze_stock` | A 股基金/ETF 代码 `5xxxxx`、`15xxxx`、`16xxxx` | “这是 ETF/基金代码，本工具不分析 ETF 自身表现” |
| `analyze_index` | 五位港股个股代码 `00700`/`00700.HK` | “这是港股个股代码，请用个股工具” |
| `analyze_index` | 基金代码或以 `ETF`/`基金` 结尾的名称 | “ETF 自身表现不能用指数报告代替” |

不自动路由的原因：ETF 可能跟踪不同指数/版本，用户可能问 ETF 自身价格或溢价；自动替换会掩盖模型错误并违反“保留用户指定标的类型”。

### 5.7 错误反馈

| 情况 | 用户反馈 | 模型约束 |
| --- | --- | --- |
| resolve 网络/5xx | 指数目录服务暂不可用，未能确认身份；本次未生成报告 | 不推断不存在，不建议替代 |
| 目录未加载/别名未加载/过期，刷新失败 | 港股指数目录刷新失败，仍使用旧目录；未能确认身份 | 同上 |
| 刷新超时 | 刷新未在等待内完成，可能仍在后台更新 | 不说“没有该指数” |
| 刷新成功但仍未收录 | 已刷新目录，仍未收录该写法；本次未生成报告；这不等于指数不存在 | 不推断不存在，不建议成分股/ETF/其他指数 |
| 已加载、别名已加载、未过期但未收录 | 目录未收录该写法；无法确认官方身份 | 同上 |
| 名称歧义 | 列出名称（代码，收益版本），请用户选择 | 不代选，不分析 |
| 市场为美股 | 美股指数暂未开放 | 不改用美股个股 |
| 市场未核验 | 市场尚未核验，暂不可分析 | 不用其他市场替代 |
| 身份已确认但行情/报告失败 | 已确认指数身份 X（名称），但行情/报告失败：… | 不用 ETF/成分股替代 |

所有失败都发送准确用户文案，并给模型一句“只回简短确认，不得扩展/替代”的 note。

## 6. 首次使用流程

以“分析恒生科技”、全新部署、无 HSI 快照为例：

1. 模型调用 `analyze_index`，参数可能是 `恒生科技`、`HSTECH` 或 `HSTECH.HK`。
2. 插件格式归一；调用 resolve。
3. 服务无 HSI 快照：`status=not_found`，`hsi_loaded=false`。
4. 插件刷新一次 `POST /indices/refresh?source=hsi`。
5. 服务拉取官方元数据，写主快照 + 别名侧车；返回 `live`。
6. 插件重新 resolve，得到 `HSI:02083.00`、`market=hk`、`return_type=price`。
7. 插件调用 `POST /api/v1/index`，只传官方身份。
8. 报告查询、下载、补发使用同一官方身份。

行为：

- 首次多等约 10～15 秒；默认 150 秒预算足够，建议 AstrBot 工具超时仍为 180 秒。
- 已有旧快照但没有侧车别名：`hsi_loaded=true`、`hsi_aliases_loaded=false`，插件自动刷新一次，用户不需要去 Web 手动刷新。
- 已有完整目录：resolve 直接命中，不刷新。
- 刷新失败：不生成报告，保留旧目录，按 5.7 反馈。

## 8. 能力边界

- 目录收录不等于报告可生成；真实行情不可取得时明确失败。
- 有行情但估值/资料缺失时，报告可生成并披露缺项。
- 历史长度不足时，部分技术指标或区间统计不可用。
- 价格指数、毛股息总收益、净股息总收益必须区分，不得混用。
- 此前真实验收过 HSI、HSCEI、HSTECH → `HSI:02083.00`、`HSI:01067.00`、A 股 `000300`；这不代表 560 条逐一验收成功。
- 不宣称“全部港股指数均可分析”。

## 11. 风险与开放点

1. **Prompt 不保证模型一定传官方名称**：`HSTECH.HK` 仍可能出现；格式归一 + 官方别名兜底。
2. **口语同义词不支持**：如果真实日志出现 `恒科` 作为参数，需要另行评估加数据行，不属于本版。
3. **官方 short name 未来重复/缺失**：resolve 返回歧义/无别名，不静默选择。
4. **侧车与主快照短暂不一致**：状态标记为未加载，插件刷新修复；回滚 v0.4.0 仍可读主快照。
5. **多进程重复刷新**：服务端原子写保证不损坏，接受重复网络请求；严格单飞需后续服务端锁。
6. **外部服务不是 v0.4.1**：插件检测 resolve 404/字段缺失，明确提示升级，不降级猜测。
7. **`legacy_hk` 兼容映射**：现有 `HSI/HSCEI/HSTECH` 价格代码去重映射可以保留或逐步数据化；它不是别名机制，不扩大为逐指数分支。
8. **目录状态字段命名**：`hsi_loaded`、`hsi_aliases_loaded`、`hsi_updated_at` 为设计基线，实施时如调整需同步插件与测试。

### 4.4 补充：匹配质量与版本 family（实施中确认）

2026-11-17 用户确认：匹配按“精确匹配 → 基名精确匹配 → 普通子串匹配”分层，命中较高层后不再混入较低层候选。每层先以官方 `indexSeriesCode` 划分 version family；同 family 内未指定版本默认价格，指定 TRI/NTRI 时选择相应版本；跨 family 一律歧义，即使其中只有一个价格条目也不得代选。没有官方 family 元数据的不同身份不推断属于同一系列。

基名从所有官方条目的名称产生，通用剔除收益版本措辞、括号及末尾“指数”；所有版本均参与匹配，避免只有总收益条目的其他 family 被价格条目遮蔽。不维护逐指数基名表。收益版本仍使用官方 `indexType`，不得从短名覆盖版本。

该 family 定义仅采用恒生官方 indexSeriesCode；其他编制方用于表示整个目录的 series_code 不作为收益版本系列，保持 A 股查询的原有标的边界。
