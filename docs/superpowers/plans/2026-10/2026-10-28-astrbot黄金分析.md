# AstrBot 黄金分析实施计划

目标：在插件提供黄金市场观察简报，复用主仓黄金接口与已有会话、队列和报告交付能力。

已确认契约：主仓 `POST /api/v1/gold` 接收 `{"refresh_cache": false}`，响应含本次 `markdown`；不查询最新报告。黄金请求统一为 `gold/GOLD`，不影响黄金股票或 ETF。未就绪进入现有最多三项的确认队列，恢复后经确认执行。

1. 测试先行：覆盖黄金 HTTP 成功、空正文、旧服务 404、超时和异常；不得泄露内部地址。
2. 注册 `analyze_gold` 工具，复用执行预算、同标的互斥、即时提示与后台交付；不修改股票与指数语义。
3. 队列和存储支持 `gold/GOLD`，覆盖去重、确认、跨重载恢复、报告交付留存和已有记录兼容；不扩大原始报告自动清理范围。
4. 增加集成测试：原文直接交付、等待服务后确认恢复、旧服务提示；检查 WebChat 及其他平台交付。
5. 对代码进行规范和质量审查；执行相关测试、Ruff、类型检查并记录既有错误。主仓正式版与插件绑定、README、更新日志及版本文本待用户独立确认，不在本次擅自改动。
6. 使用支持黄金接口的候选主仓和实际 AstrBot WebChat 验收图片或文件及等待队列；不覆盖现有正式实例，不将模拟测试称为真实服务验收。正式发布和绑定待授权后进行。

## 实施与验证记录

- 黄金接口、工具、队列、交付留存及 WebChat 确认批次已实现；黄金报告使用本次 API 响应正文。
- 针对最终产品代码的客户端、队列、等待消息、报告存储、交付与插件存储测试共 158 passed；补充股票、指数、黄金确认事件路由 4 passed；Ruff 通过。Pyright 5 个源码文件与基线均有同样 3 项既有错误。
- 本地主仓真实服务 `POST /api/v1/gold` 返回成功，耗时 15.5 秒，Markdown 9564 字符。隔离 AstrBot v4.27.4 WebChat 真实调用 analyze_gold、发送一条等待提示并交付报告，历史记录有 1 张有效 PNG；附件 HTTP 200，800×6828、2957816 字节。
- 服务器当前 AstrBot 的 `WebChatAdapter.send_by_session` 存在队列关闭竞态：隔离探针让已识别的活跃队列在发送时关闭，原框架 `_send` 拒收后返回 `None`，适配器没有补写历史或报告失败。此为现有框架问题，影响主动消息；用户已决定本次不处理，作为已知限制保留。
- 主仓新正式标签尚不存在，插件仍绑定 v0.2.2；README、更新日志、版本号与绑定等待用户确认，未更改或部署。

- 黄金等待恢复真实验收：隔离实例通过注入 `waiting_service` 记录模拟服务恢复，实际自动询问；用户确认后模型调用 `confirm_waiting_analysis`，后台发送黄金报告，历史附件 HTTP 200、PNG 800×6828，waiting/accepted 记录清除。此测试未覆盖真实首次安装或中断；QQ 未验收。
- 隔离环境首次将插件启用列表配置为空，模型未收到插件工具；改为启用插件后，DeepSeek 模型成功调用。自动选择的 GLM 模型返回限流，切换隔离环境默认模型后恢复验证；不代表所有模型均保证选择工具。
- 候选容器、独立数据目录、临时传输包和本地候选服务验收后关闭清理，正式实例未修改。
