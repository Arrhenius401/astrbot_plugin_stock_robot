# GitHub 最新正式版查询限流处理

## 已确认目标与事实

用户已确认：正常使用 Release API；仅明确限流时使用官方 latest 网页重定向；固定标签归档走 codeload，不新增 Token 配置，不回退开发分支。保持现有源码离线复用、锁定依赖、配置保留和进程所有权。

## 规则与接口

- 保留 `_latest_release(client) -> tuple[str, dict[str, Any]]` 和 download_source 的外部接口。
- 429 视为限流；403 必须带 `x-ratelimit-remaining: 0`、Retry-After 或明确的 JSON rate limit 消息。普通 403、404、网络错误和无效 API 元数据仍明确失败。
- 备用查询只请求官方 latest URL 一次，关闭自动重定向；仅接受标准重定向到 HTTPS、github.com、指定仓库 releases/tag 路径。拒绝认证信息、查询串、片段、空标签、路径穿越与无效 Git 标签字符。标签解码一次后再编码进固定标签 codeload 地址，不抓取 HTML。
- API 渠道保留 release_id；网页渠道不伪造编号。新增 release_resolution 字段，旧来源记录保持可读。所有渠道保留 release_tag、归档地址与下载摘要。
- API 与备用查询及下载共用原 300 秒总截止时间；不循环重试限流 API。备用查询失败应保留限流背景，不产生有效 instance/src。
